## Features

- **Continue a stopped reply with one click** — When a reply stops early, the Send button turns into ▶ while the input is empty. This covers rate limits, provider and network errors, replies cut off at the output limit, a Stop, and an app exit in the middle of a turn. Clicking ▶ continues where the agent left off with the model currently selected, so you can switch models first. The agent receives one short hidden note ("Continue where you left off.") and nothing new appears in the chat. With text in the input, Send works as before. For these errors, the error card's **Retry** now continues the same way instead of sending your last message again.
- **Optional auto-continue** — **Settings → AI → Performance** has two new toggles, both off by default.
  - **Continue after a rate limit resets** continues the turn when the quota resets, if the provider's error says when (for example "Resets in 40h").
  - **Continue after an app restart** continues turns that quitting the app cut off, in sessions active in the last 24 hours.
  - Task, automation and `craft run` sessions are never continued automatically, and a session is continued at most 3 times in 5 minutes.
- **Custom endpoints learn each model's limits** — For custom OpenAI- or Anthropic-compatible endpoints, Craft now reads the endpoint's model list (`/models`) at startup and after you save the connection. It fills in each model's context window, output limit, thinking support and image support where the endpoint publishes them. Magpie and OpenRouter do; plain OpenAI-style lists don't. Values already set on the connection are never overwritten.
  - Models that support thinking now receive the session's thinking level (`reasoning_effort`). If a model rejects it, set `supportsThinking: false` on that model in the connection.
  - A per-model output limit can also be set by hand as `maxTokens`.

## Improvements

- **Stop puts your prompt back only when nothing happened** — Stop returns your prompt to the input only if the reply hadn't started yet. Otherwise the input stays empty and ▶ continues the reply.

## Bug Fixes

- **Replies cut off at the output limit are no longer silent** — A reply that hit the output token limit used to end without any message, often with no text at all when the model spent the whole limit thinking. Custom endpoint models have an 8192-token limit unless one is set. These replies now show a **Reply Cut Off** card, and ▶ continues them. Claude's **Output Too Large** error continues the same way.
- **Rate-limit errors no longer promise a retry that never comes** — The card said "Will auto-retry shortly" after the retries had already run out. It now says the retries did not succeed, and shows the reset time when the provider gives one.
- **Editing a connection keeps its overrides** — Saving a custom endpoint connection in Settings used to wipe its endpoint-wide `maxTokens` and `supportsImages`, and per-model settings such as `contextWindow`. They are now kept.
